# Alice Engine · 设计思路

> 本文说的是"为什么这样设计"。怎么跑起来请看 [README](../README.md)，完整进度见 [计划](./计划.md)。English version: [DESIGN.md](./DESIGN.md)。

## 一句话

大多数 AI 角色，是一大段人设加一长串聊天记录。聊到第三十轮，人设已经被上下文稀释，她不再是她了。

Alice Engine 想换一个问法：**如果"像一个人"是工程问题，而不是写作问题呢？**

于是我们不再把性格写得更漂亮，而是把一个"人"拆成几个会各自运转、又相互牵动的系统：评价、情绪、记忆、行为、表达，再加一套能测量她有没有走样的尺子。

> 随仓库附带的示例角色 Alice：外表安静克制，内里好奇，带着一点少女心。她的情绪是她自己的，不会照着你的情绪做镜子。

## 核心主张：自我住在状态里，不住在提示词里

提示词会被挤掉，状态不会。Alice 的连续性来自一份会衰减、会耦合的情绪状态，和一套分层的记忆，而不是越来越长的上下文。换一个模型，她的"性格常量"（一份 JSON）还在；聊了很久，她的"此刻心情"还在。

## 表达分三层，彼此正交

这是整个项目里我们最喜欢的一个设计。很多项目把"说多少""带多少情绪""怎么说话"揉成一团，结果情绪一低，角色就变成吐信息的机器。我们把它们拆开：

- **内容层**决定说多少：专业、探讨、简单、低内容，四档，同时决定这一轮是回答、追问、岔开还是先去查。
- **情绪层**决定带多少情绪，只管强度。
- **语气层**决定怎么说话，始终在线：短句、口语、句末不加句号，语气词看语境自然带出，不设清单，也不强制每轮都有。

一句话概括：**情绪是旋钮，语气是嗓音。** 旋钮可以拧到最低，嗓音依然是她的。所以低情绪不等于机械，她情绪不高时依然像在跟你说话，只是色彩少一点。

情绪强度是这样算出来的：先看用户当下的情绪，再看她自己对这个话题感不感兴趣，两者合成一个"情绪基数"。

| 用户情绪 | 她的兴趣 | 情绪基数 |
|---|---|---|
| 高 | 感兴趣 | 顶 |
| 高 | 不感兴趣 | 中上 |
| 低 | 感兴趣 | 中上 |
| 低 | 不感兴趣 | 低 |

再和"这个话题需要多少情绪"取交集：查个功能不必热情洋溢，聊主观感受则不能冷冰冰。最后还有一个小设计：只有当话题的需求超过她此刻的基数时，才掷骰子让情绪随机下移 0 到 2 档，就像一个人"想热情一点，有时够得着，有时差一口气"。

## 她有情绪，而且不完全可预测

情绪不是一个"开心/难过"的标签，而是五根轴：愉悦、激活、挫败、好奇、社交亲和。它们会：

- 随时间衰减，回到各自的基线；
- 被每一轮的评价事件推动，推动幅度带一点随机扰动，同一句话不会每次都得到完全一样的反应；
- 相互耦合：挫败高的时候，负面事件会被放大；好奇高的时候，新鲜事更打动她；亲和低的时候，被冷落更难受；
- 带指向：不是笼统的"有点烦"，而是"对这件事好奇""对他有点不服"。

## 她不是一味顺从

陪伴类 AI 最常见的失败，是什么都答应。Alice 有自己的行为层：

- **压力动力学**：强命令累积的压力比软请求更多，压力会随时间衰减。压力高了，她会倾向于顶一句、岔开，或者拒绝。
- **姿态与内容正交**：除了"说什么"，每一轮还有"摆什么姿态"，回答、追问、岔开、拒绝、先查、少说两句。
- **拒绝之后会有余味**：她顶回去之后，会看对方的反应。对方接受了，她松一口气；对方继续施压，她会想"是不是我太硬了"。这份"挂心"会带进下一轮，之后才散去。
- **立场清单**：核心人格被锁住，不会被聊天自动改写；而她明确划过的线、站过的位置，会沉淀成一份可以人工编辑的立场清单，让她前后一致。

## 记忆：知道自己知道什么

记忆不是一个向量库，而是分了几种性质不同的东西：

- 短期事件（几天内）、长期槽位（工作、身体、家人、身边人……）、过期概括；
- 她自己的观点和承诺（自我模型），她说过的话也要算数；
- 对方人生里的大事；
- 被夸或被否定时留下的"情感记忆"，一句话，会影响之后的语气。

每一条记忆都标注可信度：**事实、推断、假设**三档，而且同源不降级，只有对方亲口说的才能成为事实，她自己的猜测永远不会悄悄升格。检索时综合相关度、时间、重要性、可信度四项打分（0.5 / 0.2 / 0.15 / 0.15），遗忘也是设计的一部分。

## 她会自己去做事

她不只是等你说话。她有定时的"漫游"，可以去搜索、阅读、带回见闻，并且**看和说是分开的**：先由一个资料员读完、写成报告，再由她用自己的话讲出来，避免她把资料念成书报腔。她会按兴趣画像决定去看什么（保留一部分探索位，不只是追着旧兴趣），会掷骰子决定要不要主动开口，会在睡前问候、分享见闻、好奇提问之间切换，也会写每晚一句的日记。

她还能翻看用户投喂的稿子，把目录压成"我读过什么"的概括性记忆。读文件这件事被刻意限制为**只看不写**。

## 声音：可选，且不喧宾夺主

声音是**可选的外设**，默认关闭，不接也不影响她。接入本地 GPT-SoVITS 后，她能用自己的音色说话；情绪档位会驱动语速，合成失败自动回退到浏览器朗读。参考音色由用户自备——仓库只附带一个 **CC0 公共领域**的示例音色（Piper `zh_CN-chaowen-medium`），没有任何版权包袱。

## 怎么知道它真的有效

"像不像一个人"听起来很主观，所以我们给它配了一套尺子：

- **回归集**：30 条真实对话加 13 条对抗样本，分断言、不变量、漂移三层检查；
- **语义层裁判**：用成对比较来校准，而不是让模型凭感觉打分；
- **四组剧本测试**：一致性、情境、记忆连续、演化，全部确定性，不调用 LLM；
- **反事实检验**：同一个输入，让 Alice 和一个"通用助手"各答一遍，由裁判判断区分度。如果两者太像，就说明人格被稀释了；
- **决策日志**：每一轮的内容档位、姿态、情绪档位、裁判结论都会记录，出了问题可以回头看。

## 我们走过的弯路

我们觉得诚实比漂亮更有用，所以也写在这里：

- 我们曾加过一条"语气太平就判不合格"的规则，实测会误伤干练的说话风格，违背了"语气词不强制每轮都有"的原则，于是撤掉了。语气交给语境，情绪交给档位，不再用规则硬补。
- 早期我们把"情绪低"和"语气淡"当成一回事，后来才分清：这是两个独立的维度。三层正交，正是这次纠正的结果。
- 对稿子做概括时，不能像聊天记忆那样"只转述不推断"，而要综合提炼，但每个要点都必须能在原文找到出处，不许编造。
- 用日语参考音色做跨语言合成，音调会"怪"；换成"中文变声素材当同语言参考"之后才自然——参考的语言要和目标语言一致，这是踩出来的经验。

## 现状与坦白

核心部分（人格、评价、情绪、记忆、行为、表达、自我改进、漫游与主动、评测、可选 TTS）已经落地。目前的评价层仍以规则和关键词为主，再辅以 LLM；单用户起步（状态键已为多用户预留）；运行在 DeepSeek Harness 的插件形态上。

## 你可以怎么参与

核心已经稳定，所以大块的扩展彼此独立，不需要读懂整套情绪和记忆就能认领：

- **形象**：Live2D / VRM
- **通道**：QQ 发图和表情、语音输入（ASR）、群聊、多用户
- **独立入口**：让项目脱离 DSH 也能跑起来，这会让更多人跑得起来
- **评测**：英文示例角色与英文评测集，用语义层裁判做提示词 A/B
- **人格演化的人工审核门**：让"成长"可控

如果你对"AI 的自我连续性"、情绪建模、记忆设计或评测方法感兴趣，欢迎来聊，开 issue、提想法、做实验都行。
